- Enter `nix develop`; native tools are in `nix develop .#native`. macOS requires local Xcode. ARM Linux supports JS/tooling checks; Google's Linux NDK/build-tools require an x64 build host.
- Use the dated Bun canary pinned in `.bun-version`, `nix/bun.nix` and `packageManager`. Update its archives/hashes together. Use `bun install`, `bunx`, `bun run`, `bun test`; never `npx`, npm, Yarn or pnpm.
- TypeScript everywhere on the JS side. Run built-in `bun check` after TypeScript changes. Keep strict mode, exact optional properties, unchecked index access and verbatim module syntax. No `any`, non-null assertions or unchecked casts to hide contract errors.
- Use built-in `bun lint`, `bun fmt`, and `bun fmt --check`. Do not add tsc, ESLint, Oxlint, Babel, Jest, Bob or standalone formatters. Retain tools required internally by dependencies.
- Force Bun for verified CLIs with `bunx --bun`; keep Node for native builds. Do not alias Node globally.
- Target Expo SDK 58 / React Native 0.88 and Expo Modules 2.0 beta annotations in Swift/Kotlin. No legacy RN bridge, TurboModule or Expo 1.0 DSL fallback. Verify APIs against installed SDK sources.
- This is a reusable native library. Author the config plugin in `app.plugin.ts`; Bun generates the committed `app.plugin.js` entry point. Verify freshness with `bun run build --check` and packed plugin loading under Bun and Node. Expo SDK 58 discovers TypeScript plugins, but its unpatched loader fails under Bun; consumers must not need our tooling patch or trusted install scripts.
- Own BLE through one explicitly opened session. Preserve generation checks, settle-once callbacks, serial native state, explicit close, abort handling, and native teardown. Never silently return a global constructor singleton.
- Public bytes are `Uint8Array`; normalize native ArrayBuffer output once. Keep engine Base64/JSON/positional event translation inside native code. Use typed result records and named events, with string-literal error codes.
- `example/` is the only app: Expo development builds with CNG and Noxcturnal. Its native directories are generated and ignored. BLE does not run in Expo Go or on web.
- Expo guidance: `bunx --bun @expo/agent-cli`; read `expo-overview` and applicable skills. Search with `bun run read:search-expo-docs "query"`. Restore skills with `bun run agents:setup`; sync after installs with `bun run agents:sync`.
- Run `bun run verify`, Expo Doctor, native exports and autolinking checks. Native debug/release builds (including R8) and physical BLE tests are separate evidence; report unavailable checks explicitly.
